  6283→10. Conventions et Règles du Schéma
  6284→10.1 Identifiants
  6285→ Tous les ids sont des UUID v4 générés par @default(uuid()) — pas d'auto-increment.
  6286→ Pas d'exposé des ids internes dans les URLs publiques — utiliser le slug ou la reference.
  6287→ supabaseUid est l'identifiant Supabase Auth — distinct du id MédiHelm.
  6288→10.2 Isolation multitenant
  6289→ pharmacieId est présent sur TOUTES les tables métier du schéma pharma sans exception.
  6290→ RLS PostgreSQL activée sur toutes les tables : USING (pharmacie_id =
  6291→current_setting('app.current_tenant')::uuid).
  6292→ Aucune jointure directe entre les schémas pharma et grossiste — communication via API
  6293→uniquement.
  6294→ Les données patients ne sont JAMAIS transmises au grossiste — ni nominatives, ni
  6295→agrégées.
  6296→10.3 Soft delete
  6297→ Pas de suppression physique pour les données métier — actif = false.
  6298→ Exception : OrionConversation (90j) et OrionBriefing (30j) — suppression automatique par
  6299→cron.
  6300→ Les lots avec quantite = 0 restent en base pour la traçabilité FEFO et l'audit.
  6301→10.4 Champs obligatoires
  6302→ createdAt : toutes les tables. updatedAt : tables fréquemment modifiées.
  6303→ pharmacieId : toutes les tables du schéma pharma.
  6304→ grossisteId : toutes les tables du schéma grossiste.
  6305→10.5 Stockage des fichiers
  6306→ Aucun fichier stocké en base — uniquement des URLs Supabase Storage.
  6307→ Buckets : ordonnances (privé/chiffré), documents (privé/chiffré), medicaments-photos
  6308→(public), bulletins-paie (privé/chiffré), pv-destruction (privé/chiffré).

  6673→8. Espace 6 — Vérification Authenticité Médicament
  6674→8.1 Problème adressé
  6675→La contrefaçon de médicaments est une réalité en Afrique de l'Ouest. Des patients achètent
  6676→des médicaments qui ne sont pas ce qu'ils prétendent être. MédiHelm offre un service de
  6677→vérification rapide qui interroge la base nationale des médicaments agréés DPMED.
  6678→8.2 Fonctionnalités
  6679→ Vérification par numéro de lot : le patient saisit ou scanne le code-barres/QR code
  6680→sur la boîte.
  6681→ Résultat immédiat : vert = médicament enregistré, orange = informations
  6682→incomplètes, rouge = alerte ou non trouvé.
  6683→ Informations affichées : DCI, nom commercial, fabricant, date d'expiration, statut
  6684→DPMED.
  6685→ Alerte rappel de lot : si le lot est sous alerte DPMED active — affichage en urgence
  6686→avec instructions.
  6687→ Signalement : le patient peut signaler un médicament suspect directement depuis la
  6688→page.
  6689→8.3 Ce que la vérification ne garantit PAS
  6690→La vérification confirme que le numéro de lot existe dans la base DPMED.
  6691→Elle ne garantit pas que le médicament dans la boîte correspond au numéro de lot.
  6692→En cas de doute, toujours consulter le pharmacien ou contacter la DPMED directement.
  6693→Ce message d'avertissement est affiché systématiquement après chaque vérification.
