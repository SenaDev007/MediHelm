   290→   290→   290→10. Conventions et Règles du Schéma
   291→   291→   291→10.1 Identifiants
   292→   292→   292→Tous les ids sont des UUID v4 générés par @default(uuid()) — pas d'auto-increment.
   293→   293→   293→Pas d'exposé des ids internes dans les URLs publiques — utiliser le slug ou la reference.
   294→   294→   294→supabaseUid est l'identifiant Supabase Auth — distinct du id MédiHelm.
   295→   295→   295→10.2 Isolation multitenant
   296→   296→   296→pharmacieId est présent sur TOUTES les tables métier du schéma pharma sans exception.
   297→   297→   297→RLS PostgreSQL activée sur toutes les tables : USING (pharmacie_id = current_setting('app.current_tenant')::uuid).
   298→   298→   298→Aucune jointure directe entre les schémas pharma et grossiste — communication via API uniquement.
   299→   299→   299→Les données patients ne sont JAMAIS transmises au grossiste — ni nominatives, ni agrégées.
   300→   300→   300→10.3 Soft delete
   301→   301→   301→Pas de suppression physique pour les données métier — actif = false.
   302→   302→   302→Exception : OrionConversation (90j) et OrionBriefing (30j) — suppression automatique par cron.
   303→   303→   303→Les lots avec quantite = 0 restent en base pour la traçabilité FEFO et l'audit.
   304→   304→   304→10.4 Champs obligatoires
   305→   305→   305→createdAt : toutes les tables. updatedAt : tables fréquemment modifiées.
   306→   306→   306→pharmacieId : toutes les tables du schéma pharma.
   307→   307→   307→grossisteId : toutes les tables du schéma grossiste.
   308→   308→   308→10.5 Stockage des fichiers
   309→   309→   309→Aucun fichier stocké en base — uniquement des URLs Supabase Storage.
   310→   310→   310→Buckets : ordonnances (privé/chiffré), documents (privé/chiffré), medicaments-photos (public), bulletins-paie (privé/chiffré), pv-destruction (privé/chiffré).
