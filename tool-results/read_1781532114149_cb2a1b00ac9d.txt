    69→    69→3.2 Stock & Médicaments
    70→    70→model  Medicament  {
    71→    71→Référentiel produits de l'officine — un enregistrement par DCI/forme/dosage
    72→    72→Le stock disponible n'est PAS stocké ici — il est calculé dynamiquement depuis les Lots.
    73→    73→stockDisponible = SUM(lots.quantite) WHERE dateExpiration > NOW() AND quantite > 0
    74→    74→FEFO : décrémentation prioritaire des lots les plus proches de la date d'expiration.
    75→    75→model  Lot  {
    76→    76→Lot physique d'un médicament — tracé par numéro de lot
    77→    77→CMUP recalculé à chaque réception : (ancienStock × ancienCMUP + qtéReçue × prixAchat) / (ancienStock + qtéReçue).
    78→    78→Un lot avec quantite=0 reste en base pour la traçabilité historique.
    79→    79→Les lots périmés (dateExpiration < NOW()) ne sont jamais servis en vente.
    80→    80→model  AjustementStock  {
    81→    81→Traçabilité de chaque modification manuelle du stock
    82→    82→model  InventaireSession  {
    83→    83→Session d'inventaire physique
    84→    84→Un inventaire crée un snapshot du stock théorique au moment de l'initiation.
    85→    85→La validation calcule les écarts et crée des AjustementStock pour chaque différence.
    86→    86→model  TransfertStock  {
    87→    87→Transfert de stock inter-officines (réseau promoteur)
    88→    88→Le stock source est décrémenté immédiatement à l'initiation.
    89→    89→Le stock destination n'est incrémenté qu'à la confirmation par le DIRECTEUR destination.
    90→    90→Seuls PROMOTEUR et PLATFORM_ADMIN peuvent initier un transfert inter-sites.

   290→   290→10. Conventions et Règles du Schéma
   291→   291→10.1 Identifiants
   292→   292→Tous les ids sont des UUID v4 générés par @default(uuid()) — pas d'auto-increment.
   293→   293→Pas d'exposé des ids internes dans les URLs publiques — utiliser le slug ou la reference.
   294→   294→supabaseUid est l'identifiant Supabase Auth — distinct du id MédiHelm.
   295→   295→10.2 Isolation multitenant
   296→   296→pharmacieId est présent sur TOUTES les tables métier du schéma pharma sans exception.
   297→   297→RLS PostgreSQL activée sur toutes les tables : USING (pharmacie_id = current_setting('app.current_tenant')::uuid).
   298→   298→Aucune jointure directe entre les schémas pharma et grossiste — communication via API uniquement.
   299→   299→Les données patients ne sont JAMAIS transmises au grossiste — ni nominatives, ni agrégées.
   300→   300→10.3 Soft delete
   301→   301→Pas de suppression physique pour les données métier — actif = false.
   302→   302→Exception : OrionConversation (90j) et OrionBriefing (30j) — suppression automatique par cron.
   303→   303→Les lots avec quantite = 0 restent en base pour la traçabilité FEFO et l'audit.
   304→   304→10.4 Champs obligatoires
   305→   305→createdAt : toutes les tables. updatedAt : tables fréquemment modifiées.
   306→   306→pharmacieId : toutes les tables du schéma pharma.
   307→   307→grossisteId : toutes les tables du schéma grossiste.
   308→   308→10.5 Stockage des fichiers
   309→   309→Aucun fichier stocké en base — uniquement des URLs Supabase Storage.
   310→   310→Buckets : ordonnances (privé/chiffré), documents (privé/chiffré), medicaments-photos (public), bulletins-paie (privé/chiffré), pv-destruction (privé/chiffré).
